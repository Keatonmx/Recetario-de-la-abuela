# Recetario de la Abuela (iOS)

A native SwiftUI cookbook of traditional regional Mexican recipes: home-style
methods, pressure-cooker (olla exprés) versions, and variations nested under
each dish. Everything is bundled in the app and works offline.

## What's in the app

- **Recetas**: every recipe is a lotería card (number, hand-drawn dish on a
  sunburst, the name called out the lotería way: "EL POZOLE ROJO"), grouped under
  hand-painted category signs with a talavera tile strip, with search (accent-insensitive, so
  "yucatan" finds Yucatán), category chips, and an "Olla exprés" filter.
- **Recipe screen**: Tradicional / Olla exprés / Variantes tabs, ingredient and
  step checklists that are remembered on the device, "Secretos de la abuela"
  tips, a share button, and **cook mode** (bigger text, screen stays awake).
- **Guardadas**: recipes saved with the milagro (sacred heart) button.
- **Despensa**: a chile guide with heat levels, how to prepare dried chiles, and
  a glossary of pantry staples.

## Project layout

```
web/recetario.html            The web version, and the source of all recipe text
scripts/export-recipes.mjs    Copies the recipe data from the web page into the app
Recetario/Resources/recipes.json   Generated by the script above (don't edit by hand)
Recetario/Models/             Data models and the on-device store
Recetario/Views/              SwiftUI screens and components
Recetario/Assets.xcassets     App icon, accent color, lotería card art, folk icons, talavera tile
Recetario/Resources/Fonts     Abril Fatface and Oswald in the app, Alfa Slab One for the icon script (SIL Open Font License)
Recetario/PrivacyInfo.xcprivacy    Privacy manifest (no tracking, no data collected)
project.yml                   XcodeGen spec that generates the Xcode project
.github/workflows/ios-build.yml    CI: validates the data and builds the app on macOS
```

## Adding or changing recipes

1. Edit the recipe data in `web/recetario.html` (the `R` array). Add the card's
   article ("El", "La", "Los", "Las") to `ARTICLE`, and a drawing to `ART` if
   the category's default picture doesn't fit.
2. Run `node scripts/export-recipes.mjs` to regenerate `recipes.json`.
3. Run `node scripts/render-assets.cjs "$PWD/web/recetario.html" "$PWD/Recetario/Assets.xcassets"`
   to redraw the card art and icons (needs Playwright with Chromium).
4. Commit everything. CI fails if `recipes.json` is out of sync.

## Building and running (on a Mac)

Requires Xcode 15 or newer (iOS 17 SDK).

```sh
brew install xcodegen
xcodegen generate
open Recetario.xcodeproj
```

In Xcode, select the **Recetario** target, then **Signing & Capabilities**, and
pick your Team. Choose an iPhone simulator or your own iPhone and press Run.
With a free Apple ID you can run it on your own phone; the install expires after
7 days.

No Mac? The GitHub Actions workflow builds the app on a macOS runner on every
push, so compile errors show up there.

## Publishing to the App Store

Listing text, keywords, privacy answers and review notes are in `docs/app-store.md`.
The privacy policy and support pages are `docs/privacy.html` and `docs/support.html`.

### TestFlight without a Mac

`.github/workflows/testflight.yml` archives, signs (Xcode cloud-managed signing) and uploads
to App Store Connect. One-time setup is described at the top of that file: three repository
secrets from an App Store Connect API key (the Team ID is built in). Then run the
workflow from the Actions tab, or push a tag like `testflight-1`.

`.github/workflows/app-store-screenshots.yml` makes the 6.9-inch screenshots App Store Connect
asks for and puts them on the `app-store-screenshots` branch.

### By hand, with a Mac

1. **Join the Apple Developer Program** ($99/year) at developer.apple.com.
2. **Register the bundle ID** `com.keatonmx.recetario` (or change it in
   `project.yml`) under Certificates, Identifiers & Profiles.
3. **Create the app in App Store Connect**: name, primary category Food & Drink,
   and a privacy policy URL. A short page saying the app collects no data is
   enough. In App Privacy, answer "Data Not Collected".
4. **Screenshots**: at least one set for a 6.9-inch iPhone (e.g. iPhone 16 Pro
   Max simulator, Cmd+S in Simulator).
5. **Upload a build**: in Xcode choose Product > Archive, then in Organizer
   click Distribute App > App Store Connect. Test it with TestFlight first.
6. **Submit for review.** Bump `CURRENT_PROJECT_VERSION` in `project.yml` for
   every upload, and `MARKETING_VERSION` for every public release.

Uploading without a Mac is possible from GitHub Actions with an App Store
Connect API key and fastlane. That can be added later.
